# 视频字幕转录流程（可复用于同类视频）

把**带画面硬字幕**的播客／访谈视频，整理成「按说话人分段、带时间戳、有标点」的对话原文转录 Markdown。

本文记录的是已经跑通一次的完整流程，包括踩过的坑和最终可用的参数，后续 agent 照着做即可。

> [!warning] 两条硬约束
> 1. **一切缓存、临时目录、虚拟环境都必须放在 D 盘**，不要往 C 盘写。上机前先 `source scripts/env.sh`。
> 2. **本机是笔记本（RTX 4070 Laptop 8G）**，跑 OCR 这类重活不要开高并发，优先交给 GPU 或远端 API，别把 CPU 压满。

---

## ⚠️ 换视频前必读：脚本里的参数都是这个视频专属的

本文的**流程**可以复用，但**脚本里的常量不能直接搬到新视频**。下面这些值全是照着本视频（1280×720、字幕烧在画面底部、右下角 `iamai` 水印、左下角 `WhynotTV Podcast` logo、双人对谈）标定出来的，换一个视频就必须重新确定：

| 参数 | 在哪个脚本 | 怎么重新确定 |
| --- | --- | --- |
| **有没有画面硬字幕** | 前提 | 先抽几帧看。**没有烧进去的字幕，整套方案就不适用**，只能退回 Whisper 转写 |
| 字幕带位置 `CROP_Y` / `CROP_H` | 抽帧、复检脚本 | 抽若干帧，看 OCR 返回的文本框 `y` 坐标落在哪；要包住字幕、避开底部章节进度条 |
| 水印 / logo 位置 `LOGO_MIN_X`、`LOGO_BAND_Y` | 抽帧、复检脚本 | 同样看文本框坐标：找出全片位置固定、内容不变的框（水印、频道 logo），再按坐标过滤 |
| 抽帧帧率 `FPS` | `ocr_via_api.py` | 由字幕停留时长决定；一般 1～2 fps 够用，字幕闪得快的要调高 |
| 每张对比图几条 `STRIPS_PER_SHEET` | `ocr_via_api.py` | 看画面宽度和字幕行高；放太多会把小字压糊 |
| 说话人数 `num_speakers` | `diarize_turns.py` | 双人对谈写 2；多人圆桌要改 |
| 谁是主持人 `HOST_SPEAKER` | `merge_transcript.py` | **别猜**：用总时长 + 找一句只有一方会说的话定点验证 |
| 语言 `language` | `transcribe.py` | 中文 `zh`、英文 `en`…… |
| 段落长度 `MIN_PARA`/`MAX_PARA`、平滑窗口 `SMOOTH_WIN` | `merge_transcript.py` | 按语速和节目节奏调 |
| 接口限速 `RPM_LIMIT` | 识别、加标点脚本 | 按所用平台的限额改 |

### 新视频的第一步：给视频做体检

正式开跑前先花几分钟做这几件事，后面的参数都靠它：

```bash
# 1. 看分辨率、时长、帧率
D:/ffmpeg/bin/ffprobe -v error -select_streams v:0 \
  -show_entries stream=width,height,r_frame_rate,duration \
  -of default=noprint_wrappers=1 "<视频>"

# 2. 抽几帧（分散在片头、中段、片尾，别只抽一帧）
D:/ffmpeg/bin/ffmpeg -y -ss 400 -i "<视频>" -frames:v 1 frames/sample_400.jpg

# 3. 用 OCR 打印文本框坐标，据此确定字幕带和 logo 位置
#    重点看：字幕在哪个 y 区间；有没有位置固定的水印/logo；底部有没有章节进度条
```

> [!tip] 判断字幕带的一个经验
> 中文字幕的行高通常在 30～45px。OCR 返回的文本框 `y` 范围就是字幕行位置；把裁剪带上留一点余量（上下各留 10～20px）即可。
> **底部进度条、频道 logo、台标**这几样东西经常紧贴字幕，一定先用坐标确认清楚，否则会被当成字幕混进正文。

## 0. 为什么以画面字幕为准

视频画面里的硬字幕是人工校对过的，**比语音识别准得多**。实测对比（Whisper large-v3 vs 画面字幕）：

| 位置 | 画面字幕 | Whisper 听成 |
| --- | --- | --- |
| 面试官 | John Schulman | 张师们 |
| RL 概念 | tool call（工具调用） | 推脱 |
| 学术求职 | Candidate（候选人）同台 | 同胎竞技 |
| 竞赛 | NOIP / NOI | NYP / NI |
| 数据结构 | 知识树 | 支持数 |

所以流程是：**画面字幕当正文，Whisper 只用来做交叉核对和补缺口**。

画面字幕还会带**括号释义**（如 `model release（模型发布）`、`heuristic（启发式）`、`降60（分录取）`），这些是字幕作者加的，属于原文内容，**必须保留**。

- 凭据在根目录，用 `paths.read_key()` 读。

## 3. Whisper 转写（GPU）

`transcribe.py`：用 whisperx + large-v3 出文本和时间戳。

```python
model = whisperx.load_model("large-v3", "cuda", compute_type="float16", language="zh")
result = model.transcribe(AUDIO, language="zh", batch_size=8, chunk_size=30)
```

> [!note] 两个 API 坑
> - **没有 `initial_prompt` 和 `vad_filter` 参数**（whisperx 3.8.6 的 `transcribe` 签名里没这两个），传了会 `TypeError`。
> - `DiarizationPipeline` 和 `assign_word_speakers` 不在 `whisperx` 顶层，要 `from whisperx.diarize import ...`。

转写结果先落盘成 `transcript.json`，**再**做说话人分离。因为分离可能失败（授权、显存），别让它把昂贵的转写白跑一遍。

两小时视频，large-v3 + batch 8 在 4070 上约 5 分钟。

## 4. 说话人分离

`diarize_turns.py`：export 细粒度的逐轮发言时间轴 `turns.json`。

```python
from whisperx.diarize import DiarizationPipeline
pipeline = DiarizationPipeline(model_name="pyannote/speaker-diarization-3.1",
                               token=token, device="cuda")
df = pipeline(audio=AUDIO, num_speakers=2)   # 双人对谈写死 2，比让模型猜准
```

两小时音频约 4 分钟。

```json
[{"start": 0.0, "end": 2.3, "speaker": "SPEAKER_01"}, ...]
```

### 4.1 谁是主持人、谁是嘉宾

**别靠猜**，用两条证据交叉验证：

1. **时长**：主持人说话通常明显少于嘉宾（本例 34 分钟 vs 78 分钟）。
2. **定点验证**：找一句只有一方会说的话（如开场「欢迎你来到 XXX Podcast」），看那个时间点是谁在说。

本例结论：`SPEAKER_00` = 主持人，`SPEAKER_01` = 嘉宾。

### 4.2 拿不准的时候，用说话人嵌入验证，别靠内容直觉

> [!tip] 冷开场可能是问答交替剪辑
> 本片 0:00~0:50 的引言是**问答交替**剪出来的：嘉宾片段中间插了一句主持人的话（27.6~31.9 秒）。
> 单看文字会以为整段都是嘉宾在说，差点按直觉去"纠正"分离结果。
> 用说话人嵌入一算就很清楚：该段与主播各参照段的中位 cos = **0.67**，与嘉宾各参照段只有 **0.17**。
> **分离结果是对的。** 结论：先质疑自己，再改结果。

做法（`pyannote/wespeaker-voxceleb-resnet34-LM` 跑分离时已经下到本地缓存，不用另装）：

```python
from pyannote.audio import Model, Inference
m = Model.from_pretrained("pyannote/wespeaker-voxceleb-resnet34-LM", use_auth_token=token)
inf = Inference(m, window="whole")
emb = inf({"waveform": seg, "sample_rate": 16000})    # seg: (1, N) float32 波形
```

参照段直接从 `turns.json` 里挑「整段只属于一个说话人、且 ≥6 秒」的话轮，**先验证参照可靠**：
本例两组**组内**两两 cos 中位 0.80（嘉宾）/ 0.75（主播），**跨组**只有 0.18——
分得这么开，判存疑段才可信（0.67 判给主播，0.17 判给嘉宾，一目了然）。

> [!note] 读音频别用 `torchaudio.load`
> 本机 torchcodec 装不上，`torchaudio.load` 会直接报
> `Couldn't find appropriate backend`。用标准库 `wave` + `numpy.frombuffer` 读 `audio.wav` 就行。

> [!warning] `Inference` 不传 `device` 会默认跑 CPU
> `Inference(model, window="whole")` 默认设备是 **CPU**，不是「有 GPU 就用」。
> 几千条嵌入在 CPU 上要一个多小时且毫无提示，务必写
> `Inference(m, window="whole", device=torch.device("cuda" if torch.cuda.is_available() else "cpu"))`。
> 本例 2 万多个窗在 4070 上只要 **90 秒**。

### 4.3 pyannote 会把短插话吞进长话轮，必须再用嵌入滑窗补一遍

pyannote 的**段级**分割偶尔会把一句很短的插话整个并进旁边十几秒的话轮里。本例：
嘉宾讲到一半，主持人插了一句 2 秒的追问「这些都发生在你小学的时候？」，pyannote 把它算进了
前后 11 秒的嘉宾话轮 `[461.5, 472.6]`。1.3 秒的多数投票平滑压不平一个 11 秒的段，
**按话轮怎么也修不出来**——只能在音频上换一个粒度重判。这类错误读者一眼就能看出来，
交付前必须自己先查。

`refine_speakers.py` 的做法：

1. 在整段音频上开 **2 秒滑窗、0.5 秒步长**，逐窗算说话人嵌入；
2. 只让「两个质心 cos 差 ≥0.25」的窗投票，其余弃权（交界处的窗本来也判不准）；
3. 每个 0.1 秒样本按覆盖它的窗投票，再过 **0.5 秒**中值滤波，得到一条重判时间轴；
4. 找出与 pyannote 时间轴**连续不一致 ≥1.2 秒**的区段；
5. **把区段吸附到字幕条上**——按整条字幕改判，不按滑窗跳变的位置切。

产出 `speaker_overrides.json`（`{字幕起始秒: 说话人}`）。`merge_transcript.py` 会自动读它覆盖判定，
并给这些字幕打上 `locked`——**不打标记的话，刚修好的短插话会被
「孤立短发言并入相邻段」那条规则又并回去**，等于白修。

> [!warning] 三个坑
> **① 中值滤波窗口不能开大。** 要保住的就是 1.5～2 秒的短插话，窗口一宽就被侵蚀掉，
> 再被「最短区段」阈值滤没，整个修正白做。（最初用 1.1 秒窗口，那条 2 秒的插话直接消失。）
>
> **② 字幕显示区间和实际语音差半秒左右。** 本例主持人的话在 469～471 秒，字幕却显示 468～470。
> 所以**不能按「字幕区间算平均分」来判**——邻句会把平均分抵消掉，
> 实测这条字幕的平均分只有 `-0.005`，看上去毫无异常。必须先按滑窗找出区段，
> 再按**重叠比例 ≥50%** 吸附到字幕条上。
>
> **③ 只有 1 秒的字幕不要自动改。** 实测 9 条 1 秒的候选里判错 2 条：窗口可能整个落到邻句上。
> 脚本只自动采信两种情形——**字幕本身 ≥1.5 秒**，或**整条字幕落在检出的区段里面**（重叠 100%）；
> 其余写进 `reports/refine_speakers.md` 标成「候选待复核」，交给人看。
> 本例 22 个区段 → 12 条候选 → **只自动改 6 条**。宁可少改，不要改出新的错。

滑窗打分缓存在 `speaker_windows.npz`，调阈值时直接复用（4 秒跑完），不用重算那 90 秒。

### 4.4 机器判不准的，人工定下来就别再让脚本覆盖

短插话多的地方（说话人来回抢话），自动方法仍然会错。听完原片确认过的归属，
写进本轮目录的 **`speaker_manual.json`**：

```json
{ "3228": "SPEAKER_00", "3229": "SPEAKER_01" }
```

键是**字幕起始的整秒**，值是说话人。`merge_transcript.py` 按
「先自动复核、再人工」的顺序应用，人工的最后落，机器盖不掉；命中的字幕同样打 `locked`。

> [!tip] 核对时不要只看报告里的「判定」列
> `reports/refine_speakers.md` 里的「时间轴判定」是**合并前**的标签。合并阶段还会把
> 「孤立短发言」并进相邻段，所以**交付文档里的归属可能和那一列不一样**。
> 判断某条到底归谁，一律以交付的 md 为准——否则会对着报告去改一个文档里本来就对的地方。

## 5. 提取画面硬字幕（核心步骤）

### 5.1 先定字幕带位置

抽几帧，用 OCR 看文字框落在哪：

```bash
D:/ffmpeg/bin/ffmpeg -y -ss 400 -i "<视频>" -frames:v 1 frames/sample.jpg
```

渲染成 ASCII 或直接看 OCR 返回的 `y` 坐标，确定字幕带的 `y` 起点和高度。本例 1280x720 的视频，字幕带是 **y=575、高 100**。

> [!warning] 三个必须避开的干扰
> - **右下角水印**（本例是 `iamai`，x≥1016）：字幕可到 x=1005，按位置过滤，别按文字过滤。
> - **底部章节进度条**（y≈700）：把字幕带高度压到 100 就避开了。
> - **频道 logo**（如 `WhynotTV Podcast`）：偶尔会混进来，事后检查一遍。

### 5.2 抽帧

**按 1fps 均匀抽帧**，不要用「画面变化检测」——字幕条后面的背景一直在动（人物晃动 + 压缩噪声），帧间差分根本分不出「字幕变了」还是「背景动了」。1fps 会抽到重复帧，但后面按文字去重就行，代价只是多一点识别量。

两小时视频 = 7365 帧，裁成 1280x100 的 PNG 约 180MB，可接受。

### 5.3 识别：拼对比图 + 视觉模型

**别用 CPU 跑 RapidOCR**：2fps 下 CPU 会被占满跑几十分钟，笔记本受不了。

正确姿势是把多帧**纵向拼成一张对比图**（左侧画上序号），一次请求识别多条：

```python
# 每条字幕占一行，左边留 70px 画编号，加灰边框分隔
canvas = Image.new("RGB", (im.width + 70, im.height + 16), (255, 255, 255))
dr.text((12, im.height // 2), str(label), fill=(0, 0, 0))
```

- 每张对比图放 **15 条**（实测模型能稳定对应编号，再多没试过）。
- 7365 帧 → 491 张对比图。

Prompt 要点：

```text
下面是一张纵向拼接的图片，包含 15 条视频字幕截图，从上到下已标注编号 1 到 15。
请逐条输出字幕文字，格式为「编号|文字」，每条一行。
没有文字或看不清的写「编号|（无）」。不要输出任何解释。
```

### 5.4 两条识别路线：远端视觉接口 vs 本地 GPU

两条路都跑通过，各有强弱，**建议都跑一遍，再对不一致处做裁决**。

| | 远端视觉接口 | 本地 GPU（RapidOCR） |
| --- | --- | --- |
| 速度 | 受接口限速制约（约 10 请求/分钟） | 约 0.13 秒/帧，两小时视频十几分钟 |
| 分辨率 | 拼成对比图后被压缩，小字易错 | 逐帧识别，不损失分辨率 |
| 中文 | 好 | 好 |
| **中英混排** | **好**（`OpenAI`、`GPT-4o`、`tool call` 基本不会错） | **弱**：常把 `l` 认成 `I`（OpenAI→OpenAl）、`o` 认成 `0`（GPT-4o→GPT-40），括号内容还可能顺序颠倒 |
| 依赖 | 一个 key | 显卡 + CUDA/cuDNN |

> [!important] 本地 GPU 方案的四个关键点
> **1）复用 torch 自带的 CUDA/cuDNN，必须在 `import onnxruntime` 之前设置：**
>
> ```python
> _TORCH_LIB = os.path.join(os.path.dirname(os.path.dirname(sys.executable)),
>                           "Lib", "site-packages", "torch", "lib")
> os.add_dll_directory(_TORCH_LIB)
> os.environ["PATH"] = _TORCH_LIB + os.pathsep + os.environ["PATH"]
> ```
>
> **2）onnxruntime-gpu 版本必须和 CUDA 大版本对上。** 本机是 CUDA 12，用 `onnxruntime-gpu==1.22.0`；装最新版（1.29）会报
> `cublasLt64_13.dll is missing`，因为它要 CUDA 13，静默退回 CPU。
>
> **3）压低 CPU 占用**（本机是笔记本）：单进程、`OMP_NUM_THREADS=3`、`cv2.setNumThreads(2)`，别开多进程。GPU 用上后 CPU 总占用约 27%。
>
> 验证真的跑在独显上：
>
> ```python
> RapidOCR(det_use_cuda=True, cls_use_cuda=True, rec_use_cuda=True)
> # 逐个确认三个子模型：text_det.infer / text_cls.infer / text_rec.session
> # 都应返回 ['CUDAExecutionProvider', 'CPUExecutionProvider']
> ```
>
> 任务管理器里**核显显示负载更高是正常的**——核显负责桌面显示输出，我们的计算在独显的 Compute 引擎上（可用 `nvidia-smi` 看显存和利用率确认）。
>
> **4）读图不要用 `cv2.imread`，用 `np.fromfile` + `cv2.imdecode`：**
>
> ```python
> img = cv2.imdecode(np.fromfile(path, dtype=np.uint8), cv2.IMREAD_COLOR)
> ```
>
> `cv2.imread` 在 Windows 上走的是 ANSI 编码的 `fopen`，**路径里只要有中文就一律读不出来**，
> 而且它只打印一行 `WARN ... can't open/read file` 就返回 `None`——
> 如果循环里写的是 `if img is None: continue`，整个识别会**一声不吭地跑完并产出空结果**
> （`local_ocr.json` 是个 `{}`），日志还被 cv2 的告警刷成几 MB，特别容易看漏。
> 所以：本轮目录名只用 ASCII（§1.1），读图一律用 `fromfile` + `imdecode`，
> 并且读到 `None` 要**直接报错退出**，不要 `continue`。

> [!warning] 本地识别必须处理 logo
> 本地 OCR 会把画面里的水印和频道 logo 一起读出来，还可能产生低置信度的乱码（`W/hvnotT/Padcaet` 之类）。
> 处理方式：**按文本框坐标过滤**——先探出 logo 的位置（如「字幕文字在 y=38~87，左下角 logo 在 y≥88、x<250」），低于置信度阈值的框直接丢弃。

### 5.5 接口选择与限速

| 服务 | 模型 | 备注 |
| --- | --- | --- |
| 上海交大模型平台（默认） | `qwen` | `https://models.sjtu.edu.cn/api/v1`，支持多模态 |
| DeepSeek | `deepseek-flash` | 也支持，但带推理 token，慢一些 |

> [!caution] 限速
> 交大平台限额约 **10 请求/分钟**、30 万 token/分钟。**并发开高会大量失败**（表现为模型返回内容对不上或请求报错，最后静默回退）。
> - 请求侧主动限速（滑动窗口），并发 3～6 即可。
> - 文本类任务（如加标点）**一定批量发送**，把请求数从几百压到几十。

同一平台可用的多模态模型：`qwen`、`qwen3.8-27b`；`minimax`、`minimax-m2.7`、`claw` **不支持图像**。

### 5.6 解析与去重

解析返回的 `序号|文字`，忽略水印框，然后**把连续相同的文字合并成一条字幕**（记录起止时间）。1fps 抽出的重复帧在这一步自然被合并掉。

### 5.7 补缺口

识别失败的对比图会留下空档。用「找出 `subs.json` 里 >4 秒的空档，只对这些帧重跑」的方式补齐（`fill_gaps.py`），比整体重跑便宜得多。

## 6. 合并成转录

`merge_transcript.py`：把字幕碎片按说话人归属，合并成段落。

> [!important] 必须做时间轴平滑
> pyannote 的原始输出**非常碎**：本例 1453 轮发言里，**25% 短于 0.5 秒**。直接按话轮给字幕打标签会切出几百个假切换（第一版跑出 645 段，段落中位数只有 6 秒）。
>
> 做法：把话轮重采样成 **0.1 秒粒度**的时间轴 → **1.3～2.5 秒窗口多数投票平滑** → 再给字幕打标签。
>
> 效果：发言段数 645 → 331，段落中位数 6 秒 → 15 秒。

> [!important] 话轮之间的空档不要预先填充
> 说话人切换处常有一段静音（本例嘉宾说到 60.1 秒，主持人 61.6 秒才开口）。
> 如果把空档直接算给**前一位**说话人，下一段的开场白就会被吞进上一段——
> 本例中主持人的「Hello 大家好，本期嘉宾……」差点被算成嘉宾说的。
>
> 正确做法：平滑时**只看窗口内真实存在的话轮**，整段落在静音里的样本再取时间上最近的话轮。

> [!warning] 画面标题卡/角标要人工处理
> 标题卡、频道 logo 这类画面文字**不是台词**，说话人分离会把它算给前一位说话人（因为它显示在换段前的静音处）。
> 想用「该文字在 Whisper 转写里找不到」来自动判定是**行不通的**——试过，Whisper 段落长、字符级对不齐，2440 条被误判。
> 结论：在脚本里**按视频人工列一个标题卡清单**，命中时改判给紧随其后的说话人。

其它规则：

- 字幕碎片归属：取该条中点在平滑后时间轴上的标签。
- **极短字幕要按「显示区间」判归属。** 1fps 抽帧时，只出现一秒的字幕会被记成「起止同一秒」，
  用这个零长度中点判归属会偏向前一位说话人——本例主持人问句后面粘着嘉宾接的那个「是的」，
  就是这么被算进主持人段里的。改成 `[起点, 到下一条字幕出现为止]` 的区间取中点即可，
  例如「是的」在 11.0 秒出现、下一条在 12.0 秒，中点 11.5 落在嘉宾话轮里，就归对了。
- **查标签要夹到时间轴端点。** 最后一条字幕的显示区间会伸出视频末尾（`start + MAX_DISPLAY`），
  按 `int(t / RES)` 取下标就越界了，返回 `None`，末尾那一段会被写成「未知」。
  取下标一律 `min(max(k, 0), len(timeline) - 1)`。
- 连续同一说话人的碎片合并成一段发言。
- **孤立短发言**（< 1.5 秒且两侧同一说话人）并入相邻段，去掉分离噪声。
  但 `refine_speakers.py` 复核确认过的改判（带 `locked`）**不并**——那些是真的短插话，
  不是噪声，并掉就等于把 §4.3 修好的东西又毁了。
- **这一段不切分**，同一人连续说的话就是一整段（本例平均 80 字，最长 765 字）。

> [!important] 切分要放到加标点之后做
> 合并阶段还没有标点，按字数硬切**必然切在句子中间**。第一版设了「到 110 字、遇到停顿就断」，
> 结果切出「…如何做好 engineering（工程），」/「要远比教一个 engineer…」这种断法，句子被劈成两半。
>
> 正确顺序是：**合并阶段每人一整段 → 加完标点 → 在句末标点处按语义切**。
> 加完标点就知道句子在哪结束，这时切出来的段落才读得通（见 `add_structure.py` 的 `split_sentences`）：
>
> - 按 `。！？…` 切句，累积到 180 字左右断开，上限 280 字；
> - 单句超过 280 字（说话人一口气没停），退而在逗号、顿号处切；
> - 首段带 `**[时间] 姓名：**`，**续段不重复姓名和时间戳**。

> [!caution] 不要在说话人边界处按比例切分字幕
> 一条字幕横跨两人说话时，看起来「按时间比例切开」很合理，**但试过，结果是灾难**：
> 切点会落在词中间，切出 `infra（` / `后训练强化学习基建）`、`是` / `的`、`WhynotTV` / `Podcast` 这种碎片，
> 比原来的一两个词归属错误难看得多。
>
> 正确做法是**只处理极短字幕的归属**（见上），其余边界处偶尔粘上一两个词，属于可接受的已知局限。

## 7. 加标点

画面字幕**没有标点**，读起来是连着的，必须补。

`add_punctuation.py`：**多段合并成一次请求**（每批 8 段），并要求模型按「序号|文字」返回。

> [!important] 硬校验，防止改字
> 每段返回后，**去掉标点和空白再和原文比对**，字符必须完全一致；不一致就重试，仍不一致就保留原文不加标点。
> 这样模型只会插标点，不会偷偷改字。

解析要放宽：模型经常返回 `1. 文字` 而不是要求的 `1|文字`，正则要同时吃 `|`、`｜`、`.`、`、`、`:` 等分隔符。再加一道「解析率低于 60% 就重试」的保险，避免编号错位把文字串了。

> [!warning] 硬校验挡不住「原样吐回来」
> 模型对**长段落**偶尔会一个字都不加、直接把原文吐回来。这时
> **字符完全一致，能过「没改字」的硬校验**，看着像成功，其实是白跑——
> 实测 337 字和 464 字的段都会这样，且重试同一长度仍然如此。
>
> 所以硬校验之外还要加一条「**结果不能等于原文**」，并且**失败就切块重发**
> （`punctuate_one`：整段 → 160 字块 → 90 字块）。切短之后命中率明显变高。
> 只判断「有没有标点」是不够的——原文里的括号、书名号也算标点，会漏判。

> [!caution] 续段的标点不会被复用（这个坑很隐蔽）
> `repunctuate.py` 是按「去标点后的骨架」复用旧标点的，但最初只把
> `**[时间] 姓名：**` 开头的段落收进复用表。**续段（同一人继续说下去、没有姓名和时间戳的那行）**
> 因此每次都被当成新段落重新请求；一旦某次接口回了个没加标点的，它就一直卡在那里，
> 后面的每一轮都补不上，而且看不出是哪里出的问题。
> 复用表要把**所有正文段落**都收进去，不分首段续段。

效果示例：

```text
原：幻方当时说要搞一个AI Lab（AI实验室）就是后面的DeepSeek对我当时是拿了offer
后：幻方当时说要搞一个AI Lab（AI实验室），就是后面的DeepSeek。对我当时是拿了offer，
```

## 8. 交叉核对

`compare_with_whisper.py`：把字幕全文和 Whisper 全文去标点后做 `difflib` 对齐，输出差异表 `crosscheck.md`。

本例结果：

- 字幕 34839 字 / Whisper 33403 字，**相似度 0.924**
- 字幕独有 1904 字，其中 **1066 字是字幕自带的括号释义**（不是错误）
- 81% 的差异片段长度 ≤3 字（Whisper 常吞小词）
- 长差异片段**几乎全是字幕对、Whisper 错**

> [!tip] 怎么看这份差异表
> - `delete`（字幕有、Whisper 无）：正常，多是括号释义，或 Whisper 漏词。
> - `replace` 里字幕更具体的（`John Schulman` vs `张师们`）：**字幕对**。
> - 若出现字幕明显不通顺、Whisper 通顺的地方，才需要怀疑 OCR，回看该帧确认。
>
> 本例结果：字幕比 Whisper **明显更准**，长差异片段几乎全是 Whisper 听错（`RLlib`→`RLib`、`tool call`→`推脱`）。

### 8.1 两套 OCR 互相核对（强烈建议）

远端视觉接口和本地 GPU 各有各的错，**跑两遍再对不一致处做裁决**，比任何单跑一遍都可靠。

| 典型错误 | 是谁犯的 |
| --- | --- |
| `OpenAI`→`OpenAl`、`GPT-4o`→`GPT-40`、`RLlib`→`RLIib`、`paper`→`paperr` | 本地 OCR |
| 括号内容顺序颠倒、漏字 | 本地 OCR |
| `好家翌`→`好家夥`、漏掉小词（`我也不知道`→`我不知道`） | 远端接口 |

裁决办法（`adjudicate.py`）：把两套结果不一致的帧**裁出来放大**，交给视觉模型做第三方判定，
然后三者取「多数字符一致」的那个，而不是简单选一边。

本例：288 处不一致（占 8.5%），裁决后**修正 43 处**；其余经放大复核确认接口版正确。
另外单独抽出 136 帧抽样复检，确认没有系统性错误。

> [!caution] 裁决这一步同样要限速 + 重试
> 裁决送的是**放大后**的字幕条，图更大、token 更重，是整条流程里最容易撞 429 的一步（实测第一批就 429）。
> `adjudicate.py` 除了滑动窗口限速（`RPM≈8`），还必须**撞到 429 就等着重试**：
> 原来的写法是「批次失败就 `continue`」，一旦限速会静默丢掉整批裁决结果，最后只是少修正几处，很难察觉。
> 每批失败时要打印出来，别让它悄悄过去。

> [!caution] 字级错误很难靠抽样发现
> 本例首次交付时，用户读出来一处 `好家夥`（应为 `好家翌`）。这类低频错字抽 100 多帧也未必撞上，
> 而放大重识别能稳定读对。**先质疑自己，再交付**：字幕提取的准确率不要凭直觉下结论，要实测。

```markdown
---
创建日期: YYYY-MM-DD
author:
  - <产出这份转录的模型名>
aliases:
  - "<视频标题>"
来源: <视频链接>

# <视频标题>

> [!note] 整理说明
> 本文由视频画面中的硬字幕逐条提取，按说话人合并成段，保留口语原貌与字幕自带的括号释义，
> 仅补充标点、区分说话人，未作改写。时间戳为该段发言开始的时间；同一人连续发言拆成多段时，
> 续段不重复姓名和时间。

- **主持人：** XXX（不认识就写「未在片中具名」）
- **嘉宾：** XXX
- **视频时长：** 02:02:45
- **来源：** <视频链接>

## 开场 `[00:00:00]`

**[00:00:00] 翁家翌：** OpenAI 很多这个 model release（模型发布）都有我的名字……

**[00:00:08] 主持人：** 所以整个 post-training 的 RL infra 你是最核心的贡献者了。

## 小时候的翁家翌是什么样的小孩 `[00:02:33]`

**[00:02:41] 翁家翌：** 我小时候特别喜欢学奥数，奥数我从一年级就开始学奥数……

这一段说完还没完，同一人继续说下去就另起一段，但不再重复姓名和时间戳。
```

- **要有层次结构**：章节小标题取视频简介里的时间轴，格式 `## 标题 \`[HH:MM:SS]\``；开头放主持人和嘉宾的信息块。
- 开头的属性用 Obsidian 标准字段：`创建日期`、`author`（写成列表）、`aliases`（放视频标题，方便在库里按标题找到）、`来源`。
- 按说话人分段，同一人连续说话合并成一段，**不要一条字幕一行**。
- 时间戳只保留每段发言**开始**的时间，格式 `HH:MM:SS`。
- **续段不重复姓名和时间戳。**
- 说话人姓名无法确认时用「主持人／嘉宾」，不要猜。同一档节目的其他期确认过姓名，也不能直接搬过来。
- 章节时间轴在视频简介里，记得一并抄下来。

## 10. 脚本清单

全部在 `scripts/` 下。产物路径由 `paths.py` 统一解析，写到 `$WORK` 指向的本轮目录；不带路径的中间文件都在那里，质检报告在 `$WORK/reports/`。

| 脚本 | 作用 |
| --- | --- |
| `env.sh` | 环境变量：本轮工作目录、缓存/临时目录重定向到 D 盘 |
| `paths.py` | 统一路径解析（工作目录、视频文件、凭据） |
| `extract_audio.py` | 从视频抽 16kHz 单声道音频 → `audio.wav` |
| `transcribe.py` | Whisper 转写（GPU）→ `transcript.json` |
| `diarize_turns.py` | 说话人分离，导出逐轮发言时间轴 → `turns.json` |
| `refine_speakers.py` | **嵌入滑窗复核说话人**，修掉被吞掉的短插话 → `speaker_overrides.json`、`reports/refine_speakers.md` |
| `speaker_manual.json` | （不是脚本）**人工确认过的说话人归属**，优先级最高，机器盖不掉。见 §4.4 |
| `ocr_via_api.py` | 抽帧 + 拼对比图 + 视觉模型识别字幕 → `allframes/`、`subs.json` |
| `fill_gaps.py` | 补识别失败的缺口（就地更新 `subs.json`） |
| `verify_local.py` | 本地 GPU 复检，逐帧识别 → `local_ocr.json`、`reports/local_diff.md`（加 `--reuse` 只重出比对报告，不重跑识别） |
| `adjudicate.py` | 两套 OCR 不一致处放大复核并合并 → `subs_fixed.json`、`reports/adjudicate.md` |
| `verify_sample.py` | 抽样放大复检，估算错误率 → `reports/verify_report.md` |
| `merge_transcript.py` | 字幕按说话人合并成**整段发言**（不切分）→ `transcript_new.md`（可传参指定输入输出文件名） |
| `compare_with_whisper.py` | 字幕 vs Whisper 交叉核对 → `reports/crosscheck.md` |
| `add_punctuation.py` | 首次全量加标点（带改字校验）→ `transcript_punct.md` |
| `repunctuate.py` | 字词修正后重跑：只给变化段落重新加标点，其余复用 → `transcript_final.md` |
| `add_structure.py` | **按语义切分过长发言** + 插入章节小标题和信息块 → 最终交付文件 |

典型执行顺序：

```bash
source scripts/env.sh

"$PYTHON" scripts/extract_audio.py          # 抽音频
"$PYTHON" scripts/transcribe.py             # Whisper 转写
"$PYTHON" scripts/diarize_turns.py          # 说话人时间轴
"$PYTHON" scripts/refine_speakers.py        # 嵌入滑窗复核，修短插话（跑完 ocr 之前也行，只要 audio.wav 在）
"$PYTHON" scripts/ocr_via_api.py            # 画面字幕（接口）
"$PYTHON" scripts/fill_gaps.py              # 补缺口
"$PYTHON" scripts/verify_local.py           # 画面字幕（本地 GPU 复检）
"$PYTHON" scripts/adjudicate.py             # 两套结果裁决合并
"$PYTHON" scripts/compare_with_whisper.py   # 与 Whisper 交叉核对
"$PYTHON" scripts/merge_transcript.py subs_fixed.json transcript_new.md
"$PYTHON" scripts/add_punctuation.py        # 首次全量加标点
"$PYTHON" scripts/repunctuate.py            # 产出 transcript_final.md（首次跑会全部复用）
"$PYTHON" scripts/add_structure.py          # 按语义切分 + 章节结构
```

> [!tip] 中途断了不用全跑
> 每一步的产物都落在本轮目录里，脚本会复用已有结果。比如 `transcript.json` 已存在就不会重新转写；
> `repunctuate.py` 只给内容变了的段落重新请求接口，其余复用旧标点（改完字词再跑一次，通常几次调用就够）。

## 11. 坑位速查

| 现象 | 原因 | 解法 |
| --- | --- | --- |
| C 盘空间告急 | pip 缓存和临时目录默认在 C 盘 | `source scripts/env.sh`，全部指向 D 盘 |
| 大模型下载卡在 ~110MB 不动 | hf_xet 静默中断 | `HF_HUB_DISABLE_XET=1`，走 HTTP 断点续传 |
| `GatedRepoError: 403` | pyannote 模型没授权 | HF 网页手动接受条款 |
| `TypeError: unexpected keyword argument 'initial_prompt'` | whisperx 3.8.6 没这个参数 | 去掉 |
| `module 'whisperx' has no attribute 'DiarizationPipeline'` | 导入路径变了 | `from whisperx.diarize import ...` |
| 正则取到的正文是「主持人」 | 分组数错位 | 数清楚 `(` 的层数，正文是最后一组 |
| CPU 被占满、机器卡死 | 本地 OCR 高并发 | 改用视觉 API 或 GPU，压低并发 |
| 识别大量失败/静默回退 | 撞到接口限速 | 批量发送 + 主动限速，并发 ≤6 |
| 识别一半的对比图都报 `HTTP Error 429` | 只限制了并发数，没有请求侧的滑动窗口限速（实测 6 并发裸跑：125 张失败 65 张） | 加跨线程共享的滑动窗口限速器，`RPM=9`；撞到 429 另睡 25 秒再重试。加上之后失败率归零 |
| `local_ocr.json` 只有 `{}`，识别"跑完"了却没有结果 | 本轮目录名带中文，`cv2.imread` 打不开；代码里又是 `if img is None: continue`，于是静默跳过全部帧 | 目录名只用 ASCII；读图改用 `np.fromfile` + `cv2.imdecode`；读到 `None` 直接抛异常，不要 `continue` |
| 本地 OCR 把一条字幕拼出乱序：`的一个课题（模拟）的我觉得在作为被simulate` | 一条字幕常被检测成左右两个框（中文 + 括号释义），两框 y 差几个像素，按 `(y, x)` 排序就把左右顺序颠倒了 | 先按**纵向重叠**把框聚成「行」，行内再按 x 排；拼接时去掉相邻框首尾重复的字 |
| 加标点后文字被改 | 模型自由发挥 | 去标点后硬校验字符一致，不一致就回退 |
| 某几段怎么跑都加不上标点 | 模型对长段落**原样吐回**，字符一致所以过了硬校验 | 加一条「结果不能等于原文」，失败就切块（160/90 字）重发 |
| 个别段落的标点每轮都被重新请求、还总补不上 | `repunctuate.py` 的复用表只收了首段，续段每次都当新段 | 复用表收**所有正文段落**，不分首段续段 |
| 把字幕作者的错别字当成 OCR 错误改掉了 | 只按「正常应该怎么写」判断，没回原帧确认 | 拿不准就回原帧放大到 5 倍看；**画面字幕是原文，作者写成什么就保留什么**（本例 `Sporks of AGI` 确实是字幕写的，不是 OCR 读错，已回退） |
| 说话人切换几百次、段落很短 | pyannote 输出碎片化 | 0.1 秒时间轴 + 1.3～2.5 秒多数投票平滑 |
| 下一位的开场白被吞进上一段 | 话轮间空档被预填给了前一位说话人 | 平滑时只看真实话轮，空档取时间最近的话轮 |
| 最后一段的说话人变成「未知」 | 末条字幕的显示区间伸出视频末尾，取时间轴下标越界返回 `None` | 取下标时夹到 `[0, len(timeline)-1]` |
| 冷开场里明明像嘉宾说的话却被判给主持人 | 引言常是**问答交替**剪辑，那段真的是主持人在说 | 别按内容直觉改；用 §4.2 的说话人嵌入验证 |
| 主持人夹在嘉宾长发言里的一两句追问，被算成了嘉宾说的 | pyannote 段级分割把 2 秒的短插话并进了 11 秒的长话轮，话轮级平滑压不平 | 用 §4.3 的嵌入滑窗复核补一遍；改动的字幕要打 `locked`，否则会被「孤立短发言」规则又并回去 |
| 嵌入模型慢得离谱（几千条要一个多小时） | `Inference(m, window=...)` 不传 `device` 默认跑 CPU | 显式写 `device=torch.device("cuda" ...)` |
| 嘉宾接的「是的」「对」被算进主持人问句 | 极短字幕记成零长度，中点偏向前一位 | 短字幕改用「到下一条字幕出现为止」的显示区间判归属 |
| 画面标题卡被算进前一位的段落 | 标题卡不是台词，分离结果按时间算给了前一位 | 脚本里人工列标题卡清单，改判给紧随其后的说话人 |
| 段落里出现 `infra（` / `是` 这种断片 | 在说话人边界按比例切分字幕 | 不要切；只在边界粘一两个词，属可接受局限 |
| 段落切在句子中间（`…engineering（工程），` / `要远比教一个 engineer…`） | 还没有标点时按字数硬切 | 合并阶段不切，加完标点后在句末标点处按语义切 |
